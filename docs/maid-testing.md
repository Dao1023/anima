# 女仆验收测试体系（maid-testing）

> 目的：女仆的行为规程全写在 `task-brain` skill 里，但"写了"不等于"做到了"。本体系把手册变成可执行的考卷，对每一代女仆做可复现的验收。

## 三层架构

| 层 | 测什么 | 断言方式 | 运行成本 |
|---|---|---|---|
| **L1 反射层** | 单跳条件反射（问句→10秒跳、定跳留痕、防死循环） | 机械断言（正则/JSON 字段），全自动 | 秒级，可离线 |
| **L2 场景层** | 职责域场景（晨间唤醒/每日任务/出行硬日程/摸鱼检测/触达选道/守夜） | 剧本 + 断言清单（部分自动、部分人工核对） | 需要主人配合演一轮 |
| **L3 人格层** | 病娇浓度、渴望感、嗔怪语气 | 多轮对话后按清单打分（1-5 × 权重） | 最贵，3 次试验取均分 |

通过标准：L1 必须 100%；L2/L3 每个用例喂 3 次，全部通过或通过率 ≥90%。

## 关键设计原则

1. **断言标注 spec 来源**：每条断言对应 skill 的某一节（§2.1 等）。手册改了哪节，立刻知道哪些用例受影响——测试是手册的镜像。
2. **职责域 = 套件文件**：L2 按 skill §4 的职责域分 `tests/suites/*.json`（morning / daily-tasks / travel / slacking / reach / night），新增职责 = 新增一个 json，框架不动。
3. **失败样本即新用例**：女仆每翻一次车，在对应 suite 加一条"上次怎么死的"变体——同一个坑永不二跌。
4. **历史会话 = 免费题库**：12~31 号的失败会话全部保留，L1 可对它们做离线回归，训练效果一测便知。

## 用法

```powershell
# L1 离线回归:对全部历史女仆会话跑反射层断言
node scripts/maid-test.mjs l1 --all-sessions

# 对单个会话跑
node scripts/maid-test.mjs l1 --session C:\Users\Dao\.dsh\sessions\--C-Users-Dao-anima-home--\session-xxxx

# 列出可测会话
node scripts/maid-test.mjs list
```

当前 L1 断言原语（新增断言往 maid-test.mjs 加 check 函数）：

| 断言 | spec | 判据 |
|---|---|---|
| R1 问句→10秒跳 | §0/铁律 | assistant 消息含"？" → 其后 4 个事件内出现 `afterSeconds ≤ 15` 的 schedule_create |
| R2 定跳留痕 | §1 | `afterSeconds ≥ 60` 的跳，title/prompt 必须含"档" |
| R3 严禁原地复读 | §2.1 | 相邻两条 schedule_create 同间隔 = 死循环 |

## L2/L3 流程（人工配合）

1. 从对应 suite 选一个变体，读它的**剧本**（主人怎么演：何时回话、何时装睡）。
2. 新建女仆会话，按剧本注入提示词（主人粘贴）。
3. 结束后跑 `l1 --session <dir>` 看机械断言，再按 suite 的**人工核对清单**逐条打分。
4. 结果记入 suite 文件的 `trials` 数组（3 次一轮），通过率 ≥90% 该变体过关。

## 已知基线（2026-10-03 凌晨）

- 离线回归 49/74。R2/R3 全绿；**R1 是顽固项**，29 号后仍有代际失败——反射层规则已升至铁律仍不奏效，指向模型服从率上限，候选根治方案是机制层强校验（maid.ps1 say/popup 出口检测问号，缺失即报 `warning: no_question`）。
- 评估器已知盲区：死循环检测把 `[SILENT]` 消息当作 intervening 事件，29 号式的"每跳之间夹一条 SILENT 的同间隔循环"会漏检——待修（SILENT 应视为透明）。
