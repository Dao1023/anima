		- 自定义计时器：由大脑设置的一堆，用于下次唤醒自己，周期提醒、一次性提醒、跳跃提醒等等，直接写代码跑，非常个性化
		- 计时器冲突自己解决
	- 数据后端：SQLite 数据库+配套后端，相当于档案，目前有一套规范，可以存储所有的任务
	- 意识层：对接具体 harness，可以唤醒很多 harness
- Agent：也就是大脑
	- skill：基本的交互方法，默认加载
	- 插件或MCP：看 harness 生态
	- 上下文记忆：单会话加载，这部分是 harness 管理的，和本软件无关
	- 跨会话记忆：推荐安装相关插件，也和本软件无关
	- 交互：由 harness 提供，无论是 GUI/CLI 等等，主动找用户进行交流

架构图是组成，具体状态写在上面比较混乱，这里独立介绍
- 休眠：相当于程序关机，daemon 停止运行
- 睡眠：daemon 仅保留心跳，大脑工作停止，计时器无法唤醒，但会保存唤醒记录
- 待机：低功耗模式（低 Token 消耗模式），大脑偶尔被唤醒，简单思考用户现在是否需要帮助，提醒频率在每几个小时一到几次，避免打扰用户
- 工作：AI 经常性查看用户当前在做什么，收集用户的习惯，思考有价值提高用户工作效率的方式记录下来，必要的时候提醒用户

一些争议
- 原软件：在新的架构中，原有程序仅事件层还在用，其他部分包括通知应该不需要用了
- 感知：助手没必要时刻监视用户在做什么，不需要时刻收集
- 唤醒 Token 消耗：Deepseek 报价是缓存命中 ¥0.02/M，每次在十分之一上下文窗口下，对话价格为 0.002，每小时12次，用户不在时自己睡眠，一天8小时算100次，价格为0.2元，如果加上更高频的唤醒，算5倍，1元，我觉得可以接受
